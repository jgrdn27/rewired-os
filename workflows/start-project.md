# Start a project

Resolve paths from the Rewired OS root containing `AGENTS.md` and `START-HERE.md`. Read `work/index.md` and `docs/projects.md`. Reuse an existing project or authoritative project tool when one already covers the outcome. Do not create a second status system or move existing files just to fit a template.

Use the conversation and selected context to establish the desired result, what counts as done, and the next useful action. Ask only for a missing answer that materially changes the work; keep nonblocking unknowns explicit and proposed acceptance criteria labeled as proposals. A quick task can stay in chat or one artifact. Do not turn it into a project unless requested or continuity clearly needs it.

For a new local project, start with `work/<descriptive-slug>/PROJECT.md` using `templates/project.md`. Check for an existing destination, including case-only naming differences, and preserve it. Adapt the fields to the task; do not create empty stage folders, invented deadlines, or a long intake questionnaire. For an external project, link its authoritative location from the work index and create only the missing local brief if useful and authorized. A cloud-only session follows the verified write boundary; with no write access, return an unsaved brief and state that limitation.

Link relevant wiki evidence, context, and existing deliverables rather than copying them. Use GTM playbooks only when requested or enabled and honor the user's tool choice. Project setup does not require installing a tool or activating the library.

Route the brief from `work/index.md`, keeping the index to identity, purpose, and a link. The brief identifies the status source and its last observed date. A deliverable's existence establishes neither approval nor execution. Preserve meaningful decisions and evidence when updating an existing brief.

If the request includes doing the work, continue with the next authorized action after setup; folder creation alone does not fulfill it. If the user asked only for setup, leave a precise next step. Before finishing, perform the fresh-reader check in `docs/projects.md` and report actual deliverables, remaining unknowns, and the next action. Do not claim an independent fresh-session test unless one occurred.
