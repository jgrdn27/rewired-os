# Diagnose the selected problem

Locate the Rewired root and identify the symptom or requested coverage. Begin with the affected route and a concrete example. For a broad check, sample knowledge retrieval, one work continuation, and relevant connection evidence; expand only where findings justify it.

With local execution, run `python3 scripts/knowledge.py check`. For ingestion attempts, pending sources, or freshness review, consult `docs/ingestion-health.md` and run `python3 scripts/knowledge.py health`. Use a date cutoff only for the requested review. Report the commands' actual scope. Without execution, inspect available files and leave hash/registry verification unverified.

Follow an index to its target and, for knowledge, to the original evidence. For projects, use `docs/projects.md` to check whether the artifact, completion criteria, status authority, and next step can be recovered. Distinguish your inspection from a separate assistant-session trial.

For access changes, use `docs/portability.md` to identify the same canonical files across hosts. A connection entry establishes neither authentication nor successful execution. A routine requires an observed due result to count as executed. Do not make live writes, connect accounts, or install software just to obtain a passing result.

Describe each checked area as working, needs attention, or unverified. Attach the observed evidence and limitation. Empty user records are normal in a stock installation. Missing tests are not operational failures, and timestamps alone do not prove freshness.

Prioritize up to three supported findings with their consequence, proposed remedy, and completion check. Do not fill a quota. Return the report in chat unless saving was requested; then use a unique dated `reviews/` record and a useful route. Apply repairs only when authorized.
