# Review results

Resolve the Rewired root. Read only the work records, goals, and prior review relevant to the chosen period. Establish what was delivered and what evidence shows its effect. Label incomplete coverage and reported outcomes.

Give the useful findings before requesting more context. If the record is too thin, ask a focused question or return a limited review. Never invent activity to populate a report.

Find a consequential source of friction, if one is supported: repeated revisions, missing inputs, failed continuation, unnecessary steps, or unreliable execution. Describe its practical effect and propose a bounded change with an observable success check. A no-change conclusion is valid.

When implementation is included in the user's request, act on the selected change using existing authorization. When the user requested review only, leave the recommendation reviewable. Improve an existing process where appropriate; do not require a new automation, skill, tool, or maturity stage. External communication, spending, and scheduling remain limited to their authorized scope.

Save a unique dated review under `reviews/` only when durable or recurring review records were requested; provide a route from the relevant work record. Preserve prior reviews. Include evidence, proposed or accepted changes, and the next observation needed.

Compare later outcomes only using comparable real records. A synthetic test is verification of that test case, not proof of adoption, time saved, or business impact.
