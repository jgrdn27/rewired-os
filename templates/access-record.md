# Access route template

Copy a completed entry into `connections.md` only after establishing the intended scope. Leave unknown fields unknown. Never include secrets.

- Purpose and owning activity:
- Host/application and device:
- Provider and intended account/workspace:
- Canonical folder URL/ID; local root if applicable:
- Anchor file relative path and cloud ID:
- Access method: local / synced-local / connector / API / snapshot.
- Permitted read and write areas:
- Complete read verified at; file/revision or hash; result:
- Write verified at; unique test artifact; readback result:
- Cross-route sync verified at; second route; result:
- Capability observed: reader / contributor / maintainer / executor.
- Designated wiki writer and handoff route:
- Offline availability and freshness limits:
- Credential storage method (never the value):
- Tool/version and next recheck trigger:

Use **unverified** for an untested capability. A successful read on one device does not verify writes, another account, or another assistant.

For an ingestion route, also record the last attempted run and outcome, latest successful useful read, observed failure if any, and expected cadence only if configured. Link the actual run evidence. A configured route without execution evidence remains unverified.
